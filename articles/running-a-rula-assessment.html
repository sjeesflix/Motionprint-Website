Running a RULA Assessment

This article walks through a complete RULA assessment in Motionprint Ergo, from selecting the report type to processing the result. RULA differs from the lifting methods in one important way: instead of defining lifting moments, you define posture tasks — windows of time in which the worker holds or repeats a particular working posture. If you have not read Understanding the RULA Assessment yet, it is worth doing so first, since the inputs here map directly onto the method's scoring.

1 Overview

A RULA assessment follows the same overall flow as every other report in Motionprint Ergo:

1
Select the report type

Choose RULA from the report selection screen.

2
Choose and set up an input source

Load an Xsens recording and enter the general information for the assessment.

3
Trim the recording and define posture tasks

Mark the windows of the recording that represent the postures you want assessed.

4
Provide task information and process

Enter the inputs RULA cannot observe, then run the assessment.

Most of the work is in step 3. Deciding which parts of a recording constitute a distinct posture task is the judgement call that shapes the whole assessment, and it is worth thinking about before you start clicking.

2 Select Report

From the Create screen, choose RULA. The report type determines which inputs you are asked for and which calculations run — it cannot be changed later without starting a new assessment, so make sure RULA is the right method for the task.

Choosing between methods

RULA assesses upper-body posture. If the task is fundamentally about lifting a load, NIOSH or KIM-LHC will tell you more. Nothing stops you running both on the same recording — they answer different questions, and a task can easily be acceptable under one and problematic under the other.

3 Select Input Source

Motionprint Ergo offers three input sources:

SourceDescription
MVNX FileUpload an Xsens recording as a .mvnx file exported from MVN Analyze.
Xsens RecordingUse a recording made within Motionprint Ergo itself. These are stored in the app.
Markerless Video CaptureComing soon.

For most workflows you will use MVNX File. The file is validated on load — if the recording is unreadable or its length cannot be determined, you will be told before going any further.

4 Set Up Your Input Source

Once the recording is loaded, you enter the general information that will appear on the report: the subject's details, the Operator and Evaluator names, and the assessment date. Which of these fields appear, and which are hidden from the finished report, is controlled by your privacy settings.

The 3D viewport initialises at this point. You can orbit, pan and zoom the model, and switch camera views — the default layout and camera angles come from your RULA report settings.

5 Define Posture Tasks

This is the heart of a RULA assessment. Use the trim handles on the playbar to narrow the recording to the period you want to assess, then create one or more posture tasks within it.

A posture task is a frame range representing a working posture you want scored. Each has a start frame and an end frame, and must be at least one second long — shorter windows are rejected, because muscle use cannot be judged from a fraction of a second.

GIF
Creating a posture task on the timeline

Dragging the trim markers, then marking a posture task frame range — the equivalent of the lifting-task GIF in the NIOSH article.

How many tasks should you create?

There is no single answer, but the principle is straightforward: one task per distinct posture. A worker who spends a shift alternating between reaching into a bin and assembling at a bench is adopting two different postures, and they should be two tasks. Splitting them keeps each score interpretable — a single window spanning both would report only the worse of the two and tell you nothing about the other.

Conversely, if the worker repeats the same posture many times, you do not need a task for every repetition. One representative window is enough, and the repetition itself is captured by the muscle use point rather than by the number of tasks.

Tasks are scored independently

Each posture task gets its own RULA score. There is no equivalent of the NIOSH Composite Lifting Index that aggregates them, because RULA has no cumulative model — the method describes a posture, not a shift. If you want a single figure across several tasks representing the same repeated posture, enable Generate averaged overview in the settings.

6 Provide Task Information

For each posture task you supply the inputs that cannot be derived from motion data. There are four, and each maps onto a specific part of the RULA score:

FieldWhat it affects
DescriptionLabels the task in the report. Not used in scoring.
Load weightSets the force/load points, from 0 to 3, added to both Table A and Table B.
Arm supported / leaningSubtracts 1 from the upper arm score, floored at 1.
Shock / rapid build-up of forceForces the maximum force/load points regardless of weight.

The shock flag deserves a moment's thought. It describes how the force is applied rather than how much of it there is — hammering, snapping a component into place, absorbing a power tool's torque reaction. Because it overrides the weight bands and applies to both score groups, enabling it can move the final RULA score by two points. Set it when the work genuinely involves impact, and leave it off otherwise.

Muscle use is automatic

Unlike the load inputs, muscle use is computed for you. Motionprint Ergo checks each posture task for a mainly static posture or a repeated action, and it does so separately for the Wrist & Arm group and for the Trunk, Neck and Legs group. A task can therefore attract the muscle use point in one group and not the other — which is realistic, since a worker can hold the trunk still while the arms repeat a cycle.

Why the one-second minimum matters

Muscle use is judged from how long a posture is held and how often an action repeats. A window shorter than a second gives no basis for either, which is why the app rejects it. If a posture genuinely only occurs for a fraction of a second, it is a transient rather than a working posture — and the peak-frame logic will catch it anyway within a longer task.

7 Processing the Assessment

Before the Process button becomes available, the app checks that everything it needs is present: an MVNX file, at least one posture task, and the required fields for every task. If anything is missing, you get a list of exactly which items to complete rather than a generic error.

Processing scores every frame of every posture task, for both sides of the body, then reduces each task to its peak frame. When it finishes you are taken to the results view.
