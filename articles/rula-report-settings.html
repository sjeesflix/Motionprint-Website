RULA Report Settings

7 min read
Last updated August 2026
RULA
In this article
  • 1. Overview
  • 2. Analysis & Scoring
  • 3. Viewport
  • 4. Export
Back to Knowledge Base

The RULA Report Settings page is your central configuration hub for all RULA assessments in Motionprint Ergo. Settings you choose here become persistent defaults applied to every new assessment — whether you need to control automatic detection, customize your report layout, or control export filenames. Changes take effect the next time you open or run an assessment.

1 Overview

The settings page is accessed via Sidebar → Settings → Reports tab. At the top of the first card a report-type dropdown lets you select which report methodology to configure — select RULA here. Switching with unsaved changes triggers a confirmation dialog. All configuration options are displayed as a stacked set of modular cards.

At the bottom of the card stack, an action bar provides a single Save and apply button. Clicking it saves your changes to preferences; the page stays open and the button becomes disabled until you make further changes. There is no dedicated Discard button — if you navigate away with unsaved changes, a confirmation dialog appears asking whether you want to leave; choosing "Yes" discards the changes implicitly.

The settings are organized into three functional modules, each addressing a specific aspect of how RULA assessments are performed, displayed, and exported. Each module contains toggles, dropdown selectors, text inputs, or custom lists depending on the type of setting.

Settings are global defaults

All settings apply to every RULA assessment created after you save them. They are stored locally on your system and persist across sessions. If you need different settings for a specific assessment, you can adjust them within that assessment before running the analysis — the global defaults do not lock you in.

No Input & Data module

Unlike the lifting reports, RULA has no reference mass or analysis mode to configure — its scoring bands come from the published method and are not user-adjustable. Fields such as gender, age and weight are controlled globally in Sidebar → Settings → Privacy rather than per report type. See Privacy Settings.

2 Analysis & Scoring

The Analysis & Scoring module determines what is detected automatically, whether an averaged result is produced, and which optional tabs are available.

SettingDefaultDescription
Auto-generated critical moments On Toggle automatic detection of the peak moment and sustained risk periods in the In-depth analysis tab. Uses peak detection (the highest-scoring frame) and sustained risk detection (the highest average score over at least 1 second). Disable if you prefer to mark critical moments manually.
Generate averaged overview Off Toggle to add an averaged result across posture tasks to the score overview and export files. Use only when all posture tasks represent the same repeated posture.
Findings enabled On Toggle whether the Findings tab appears in the report. When disabled, the tab is hidden entirely.
Findings title "Findings" Text input to rename the Findings tab. The custom title appears in the report tab bar and in exported files.
Findings sections 5 defaults Drag-and-drop list of section blocks within the Findings tab. Add, rename, reorder, or delete sections. A Reset to defaults button restores the standard five sections.

Averaged overview explained

Off is the recommended default for most assessments. Each posture task is scored independently and reported on its own, which is what you want whenever the tasks describe different working postures — a task scoring 3 and a task scoring 7 are two separate findings, and the 7 is the one that needs attention.

On adds an Average (all tasks) entry to the posture task selector, showing a single averaged result alongside the individual ones. Choose this when your recording captures one repetitive operation split into several cycles, where the average is a fair summary of a consistent posture.

Only average what is genuinely comparable

Averaging across genuinely different postures produces a number that describes none of them. Before enabling this, check that every posture task in the assessment represents the same repeated posture — otherwise leave it off and read the tasks separately.

Findings tab configuration

The Findings tab in the report (if enabled) is a free-form documentation area. You can customize it from this module:

  • Enable/Disable — toggle whether the Findings tab appears in the report at all.
  • Tab title — text input to rename the tab. Default is "Findings".
  • Sections list — add, rename, reorder (drag-and-drop), or delete individual section blocks within the Findings tab. Each section has a title and a multi-line text area for notes.
  • Reset to defaults — button to restore the standard section structure: Current Situation, Observations, Risk Assessment, Recommendations, and Conclusion.

3 Viewport

The Viewport module sets the default 3D viewer layout and camera angle for both the input page and the In-depth analysis tab on the results page, ensuring consistent visualization across your assessments. The same two settings apply to both pages:

SettingOptionsDescription
Layout Single view, Two horizontal, Two vertical, Four views Controls how many viewports are shown. Single view shows one full-width viewport. Two horizontal shows two viewports side by side. Two vertical stacks them. Four views shows a 2×2 grid.
Camera view Perspective, Front, Back, Left, Right, Top Sets the default camera angle. Perspective is a realistic angled view. The others are orthogonal views useful for checking posture alignment from a specific direction. When a multi-viewport layout is selected, each viewport has its own camera view setting.
Worth setting for RULA in particular

Because RULA scores posture rather than load, judging a result usually means looking at the body from a consistent angle. A side view shows trunk and neck flexion directly; a front view shows abduction and side bending. Choosing a two-view layout with both saves orbiting the model on every assessment. These are defaults only — you can still change the layout or orbit freely inside a report.

4 Export

The Export module controls the naming conventions for PDF and Excel files when you export a completed RULA assessment report, and what those files contain.

Filename templates

PDF and Excel exports each have their own filename template, both defaulting to:

{workstation}_{current_date}_{report_type}

The two templates are independent — you can customize them separately. The file extension (.pdf, .xlsx) is appended automatically. For a full overview of available variables, validation rules, fallback behaviour, and example templates, see Exporting Reports (PDF & Excel).

A separate Project Save template controls the default title pre-filled when saving an assessment to the Projects Database. It uses the same variable syntax. See Projects Database — Project title naming template for details.

Export settings

SettingDefaultDescription
Use company branding Off Toggle to include your company logo and brand colour in exported PDF and Excel reports — on the cover page, section headers, and footer. When disabled, exports display "Motionprint" as the default footer company name.
Export only average posture task Off Toggle to export only the averaged result rather than every individual posture task. Requires Generate averaged overview to be enabled first — without an average to export, the option has nothing to act on and stays unavailable.
Company branding is configured in General Settings

The company name, logo, and brand colours are configured in Sidebar → Settings → General, not here. Set them there once and they apply to all branded exports across all report types. See Customization & Branding for a full walkthrough.

Exporting only the average hides the individual tasks

The combination produces a short report describing one representative posture, which is right for a repetitive single-operation assessment and misleading for anything else. If in doubt, export everything — a reader can skip a task they do not need, but cannot recover one that was never included.

How settings affect reopened projects

When you reopen a saved project from the Database, Motionprint Ergo may ask whether to use your current settings or the saved settings from when the project was originally created. Your choice determines whether the analysis recalculates with your latest configuration or preserves the original methodology. See Projects Database for details.
